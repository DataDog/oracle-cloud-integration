# Purpose

This folder contains definitions for all of the function images used by the DataDog OCI integration

# Creating docker image

## Local build

- Make sure the current directory is in `datadog-functions`
- For metrics forwarder build, run `docker build -f Dockerfile-metrics --tag <repository-host>/<repository-name>:<tag>  .`
- For log forwarder build, run `docker build -f Dockerfile-logs --tag <repository-host>/<repository-name>:<tag>  .`
- For events forwarder build, run `docker build -f Dockerfile-events --tag <repository-host>/<repository-name>:<tag>  .`

## Multi-region build & push (`docker-images.sh`)

`docker-images.sh` builds and pushes all three forwarder images (metrics, logs, events) to every subscribed region (or a filtered subset) in one run, using `docker buildx` for multi-arch (`linux/amd64` + `linux/arm64`).

### Prerequisites

1. **OCI CLI** installed and configured (`~/.oci/config`) for the target tenancy. The realm (OC1 commercial, OC2 US Gov, OC3 US DoD) is inferred automatically from the OCI CLI's region-subscription list.
2. **jq** installed.
3. **Docker buildx** installed (`docker buildx version`).
4. **Push access** to OCIR in every target region.
5. A container registry repo created in each target region with the names:
   - `oci-datadog-forwarder/metrics`
   - `oci-datadog-forwarder/logs`
   - `oci-datadog-forwarder/events`

### Realm support (registry host auto-detected)

The script detects the realm from each region's identifier and builds the correct OCIR host automatically:

| Realm | Example regions | Registry host format |
|---|---|---|
| **OC1 commercial** | `us-ashburn-1`, `us-phoenix-1` | `<region-key>.ocir.io` (e.g. `iad.ocir.io`) |
| **OC2 US Gov / FedRAMP** | `us-langley-1`, `us-luke-1` | `ocir.<region>.oci.oraclegovcloud.com` |
| **OC3 US DoD** | `us-gov-ashburn-1`, `us-gov-chicago-1`, `us-gov-phoenix-1` | `ocir.<region>.oci.oraclegovcloud.com` |

Commercial registries use the short 3-letter region key; Gov/DoD/Sovereign registries use the full region identifier. You do **not** need to specify the realm manually — just enter the region identifiers when prompted.

### Run

```bash
cd datadog-functions
./docker-images.sh
```

You will be prompted for:
- **Docker username** — your OCI IAM username (the auth token is the password).
- **Tenancy namespace** — the OCIR object namespace for your tenancy (e.g. `iddfxd5j9l2o` for the Datadog public namespace; use your own tenancy namespace for private deployments).
- **Docker password** — an OCI auth token (not your OCI console password).
- **Docker image tag** — e.g. `v1.0.0`.
- **Regions** — comma-separated region identifiers (e.g. `us-phoenix-1,us-ashburn-1`), or press Enter to build for all subscribed regions. For Gov/DoD, use the full identifiers (e.g. `us-langley-1,us-gov-ashburn-1`).

Before pushing, the script prints the computed registry host for each region so you can verify the realm detection. It then asks for confirmation before building and pushing.

### Notes for Gov / DoD / Sovereign tenancies

- The OCI CLI must be configured for the Gov/DoD realm (the realm is baked into the CLI's endpoint discovery via `~/.oci/config`); the script relies on `oci iam region-subscription list` returning the correct realm-specific regions.
- OCIR is realm-isolated: each realm has its own Datadog-published image namespace. The `datadog-terraform-onboarding` stack auto-detects the realm from the tenancy OCID prefix (`ocid1.tenancy.oc2.` → OC2 US Gov, `ocid1.tenancy.oc3.` → OC3 US DoD) and pulls the forwarder images from the matching realm namespace on the correct OCIR host (`ocir.<region>.oci.oraclegovcloud.com`), so no manual namespace configuration is needed when deploying through that stack. If you are pushing the images yourself (e.g. into a private in-realm namespace), pass that namespace when prompted here and point the Terraform at it.
- **Manual `docker login` to a Gov/DoD registry must use `--password-stdin`**, not the interactive password prompt. The interactive prompt can fail with `unknown: Unauthorized` because Docker's default login flow doesn't match the registry's auth challenge. Use:
  ```bash
  echo '<auth-token>' | docker login ocir.<region>.oci.oraclegovcloud.com -u '<namespace>/<username>' --password-stdin
  ```
  where `<auth-token>` is an OCI auth token (not your console password) generated by a user in the same realm's tenancy. The `docker-images.sh` script already uses `--password-stdin`, so it is unaffected.
